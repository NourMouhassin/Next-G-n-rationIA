This site is the single reference for the module. It is updated in place: the pack version in the header identifies what you read. Resources marked Final are stable; resources marked Beta may still change before their session.

Your path

  1. Before 21 October: get your machine ready. Before TD 1 gives the steps: download the student ZIP, install Python, create your two free accounts, run the access check and read the TD 1 assignment. Allow about 45 minutes. Preparation was due by Sunday 18 October 2026; the environment is checked when the lab opens at 13:30. The school provides no account and no computing budget: the work runs on your own machine, with free Groq and OpenRouter accounts.
  2. 21 October, TD 1 (Final): compare. Five free models on twenty questions, against a reference your sub-group computes itself. TD 1 assignment.
  3. 18 November, TD 2 (Beta): vote and route. The k-of-n vote, the wrong consensus, the routing rule. TD 2 assignment.
  4. 11 December, TD 3 (Beta): quantify and decide. The cost of each configuration, the decision for a named use case, the three slides. TD 3 assignment.

You work in sub-groups of six to eight within your DIA: 33 sub-groups for the 228 students. After each session, add a Markdown report to the sub-group's shared public Git repository and update the same Moodle hand-in entry with the repository URL, the session's commit and the report link, by 23:59 Paris time on the following Sunday (25 October, 22 November, 13 December): see Hand-in. Each lab session ends with an individual fifteen-minute quiz on Moodle: see Assessment.

Each assignment ends with what is valued. A sub-group ahead of schedule can formalise its routing rule with more precise tests between TD 1 and TD 2, and automate its comparison; the instructors propose these tracks in the session.
